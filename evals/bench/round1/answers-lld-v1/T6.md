# In-process cache: per-entry TTL, LRU at fixed capacity, concurrent, slow loader

## 1. Assumptions and scope

- One JVM, many threads calling `get`/`put`. The backing DB is the source of truth; `load(key)` takes ~50 ms.
- Read-through: a miss loads from the DB. `put` stores a value the caller already has (for example after it wrote the DB); write-through/write-back policy is a wrapper, not part of the core.
- TTL counts from when the value was loaded or put, not from last access (idle expiry is a different feature).
- Guarantees: at most `capacity` entries (in-flight loads count); one DB load per key at a time however many threads miss together; a `put` is never overwritten by an older load that finishes after it; callers never block inside the cache.
- Skipped: cross-node consistency, refresh-ahead, weighted size, stats. In production I would use Caffeine (`AsyncLoadingCache` with `expireAfter` and `maximumSize`); this is the core you would write if you could not.

## 2. API

```java
public interface Loader<K, V> {
  CompletableFuture<Loaded<V>> load(K key);          // value + its TTL; runs on the loader's own IO pool
}
public record Loaded<V>(V value, Duration ttl) {}

public final class TtlLruCache<K, V> {
  public CompletableFuture<V> get(K key);              // hit: completed future; miss: shared in-flight load
  public void put(K key, V value, Duration ttl);       // in-memory only, O(log n), no IO
  public void invalidate(K key);
}
```

`get` returns a future because a miss does 50 ms of IO: a request thread must not wait on it, and the signature says so. `put` is purely in memory, so it returns `void`.

## 3. Data structures

| Structure | Key -> value | Answers | Cost |
|---|---|---|---|
| `LinkedHashMap<K, Entry>` with `accessOrder=true` | key -> entry | lookup, and recency order for LRU (eldest = least recently used) | get/put/remove O(1) |
| `TreeSet<Entry>` ordered by `(expiresAt, seq)` | entries by expiry time | "is anything already expired?" before evicting a live entry | add/remove/first O(log n) |
| `Entry` | key, seq, `CompletableFuture<V>`, `expiresAt` | the value or the in-flight load | |

Why two indexes: LRU order and expiry order are independent. With per-entry TTL, the least recently used entry is not the one that expires first, so one ordering cannot serve both. When full, first drop an entry that is already expired (it is useless anyway), and only then evict the LRU live entry.

`seq` (a counter) breaks ties so two entries with the same `expiresAt` are both kept in the `TreeSet`. `expiresAt` is set once, before the entry enters the `TreeSet`, and never changed while it is in there; changing a sort key inside a tree corrupts it.

Per operation: hit O(1); miss O(log n) to insert the placeholder plus O(log n) when the load completes; `put` O(log n); eviction O(log n).

## 4. Concurrency plan

| Shared state | Mechanism | Why |
|---|---|---|
| The map + the expiry index together | **One `ReentrantLock` over the composite** | They must agree: an entry in one and not the other is a leak or a wrong victim. `ConcurrentHashMap` + `ConcurrentSkipListSet` are each safe, but "remove from map, remove from index" across both can still be torn. Also, LRU makes every `get` a write (it reorders), so a read-write lock buys nothing |
| The DB load | **Outside the lock**, on the loader's executor | The lock is held for O(log n) pointer work only, never for IO |
| Concurrent misses on one key | **The map stores the future**, inserted under the lock on the first miss | Later callers find the in-flight entry and share the same future: one DB call for N callers (request collapsing) |
| Load finishing after a `put` or `invalidate` | **Identity check**: the completion only indexes the entry if `map.get(key) == thisEntry` | Without it, a load that started at t=0 and finished at t=60 ms would overwrite a fresher `put` from t=10 ms |

Rules I hold to:
- Never complete a future while holding the lock: `thenApply` callbacks of waiting callers would run under it.
- Never call the loader under the lock.
- Hand callers `future.copy()`, so one caller cancelling or completing its future cannot affect the shared one.
- A failed load is removed, so the next `get` retries instead of everyone getting the cached error.

Rejected:
- **`synchronized get` that calls `load` inside:** every thread waits behind a 50 ms DB call; throughput collapses to ~20 misses per second.
- **Per-structure concurrent collections without a lock:** torn updates between map and index (see above).
- **Keyed single-thread executors (route key K to lane `hash(K) % N`):** gives per-key ordering without locks, but costs a thread hop on every hit and a slow task blocks its whole lane. The identity check gives the ordering I need (put beats an older load) more cheaply.
- **Lock contention at very high thread counts:** if profiling shows the single lock hot, stripe into S segments by key hash, each with its own lock, map, index and `capacity / S`. LRU becomes approximate per segment. I would not start there.

## 5. Code

```java
public final class TtlLruCache<K, V> {

  private static final class Entry<K, V> {
    final K key;
    final long seq;
    final CompletableFuture<V> value;
    long expiresAt = Long.MAX_VALUE;           // set once under the lock, before entering byExpiry
    boolean loaded;                            // false while the load is in flight

    Entry(K key, long seq, CompletableFuture<V> value) { this.key = key; this.seq = seq; this.value = value; }
    boolean expired(long now) { return loaded && now >= expiresAt; }
  }

  private final int capacity;
  private final Loader<K, V> loader;
  private final Clock clock;

  private final ReentrantLock lock = new ReentrantLock();
  private final LinkedHashMap<K, Entry<K, V>> entries = new LinkedHashMap<>(16, 0.75f, true); // access order
  private final TreeSet<Entry<K, V>> byExpiry = new TreeSet<>(
      Comparator.<Entry<K, V>>comparingLong(e -> e.expiresAt).thenComparingLong(e -> e.seq));
  private long seq;                             // guarded by lock

  public TtlLruCache(int capacity, Loader<K, V> loader, Clock clock) {
    if (capacity <= 0) throw new IllegalArgumentException("capacity must be positive: " + capacity);
    this.capacity = capacity; this.loader = loader; this.clock = clock;
  }

  public CompletableFuture<V> get(K key) {
    long now = clock.millis();
    Entry<K, V> e;
    boolean mustLoad = false;
    lock.lock();
    try {
      e = entries.get(key);                     // hit moves it to most-recently-used
      if (e != null && e.expired(now)) { removeLocked(e); e = null; }
      if (e == null) {
        e = insertLocked(key, new CompletableFuture<>(), now);
        mustLoad = true;                        // only the first misser loads
      }
    } finally {
      lock.unlock();
    }
    if (mustLoad) startLoad(e);
    return e.value.copy();
  }

  public void put(K key, V value, Duration ttl) {
    long now = clock.millis();
    lock.lock();
    try {
      Entry<K, V> old = entries.get(key);
      if (old != null) removeLocked(old);      // also drops it from byExpiry: no index pollution
      Entry<K, V> e = insertLocked(key, CompletableFuture.completedFuture(value), now);
      markLoadedLocked(e, now, ttl);
    } finally {
      lock.unlock();
    }
  }

  public void invalidate(K key) {
    lock.lock();
    try {
      Entry<K, V> e = entries.get(key);
      if (e != null) removeLocked(e);
    } finally {
      lock.unlock();
    }
  }

  // ---- load path: IO outside the lock ----

  private void startLoad(Entry<K, V> e) {
    CompletableFuture<Loaded<V>> f;
    try {
      f = loader.load(e.key).orTimeout(2, TimeUnit.SECONDS);
    } catch (RuntimeException ex) {
      f = CompletableFuture.failedFuture(ex);
    }
    f.whenComplete((loaded, err) -> {
      long now = clock.millis();
      lock.lock();
      try {
        boolean current = entries.get(e.key) == e;   // a put/invalidate/eviction may have replaced it
        if (err != null) {
          if (current) removeLocked(e);              // do not cache failures
        } else if (current) {
          markLoadedLocked(e, now, loaded.ttl());
        }
      } finally {
        lock.unlock();
      }
      // complete outside the lock: waiting callers' callbacks must not run under it
      if (err != null) e.value.completeExceptionally(err);
      else e.value.complete(loaded.value());
    });
  }

  // ---- the only insert and remove paths: keep both indexes in sync ----

  private Entry<K, V> insertLocked(K key, CompletableFuture<V> value, long now) {
    makeRoomLocked(now);
    Entry<K, V> e = new Entry<>(key, seq++, value);
    entries.put(key, e);                          // in-flight placeholder counts toward capacity
    return e;
  }

  private void markLoadedLocked(Entry<K, V> e, long now, Duration ttl) {
    e.expiresAt = now + ttl.toMillis();           // sort key set before insertion, never after
    e.loaded = true;
    byExpiry.add(e);
  }

  private void removeLocked(Entry<K, V> e) {
    entries.remove(e.key);
    if (e.loaded) byExpiry.remove(e);
  }

  private void makeRoomLocked(long now) {
    while (entries.size() >= capacity) {
      Entry<K, V> soonest = byExpiry.isEmpty() ? null : byExpiry.first();
      if (soonest != null && soonest.expired(now)) {   // compare with now; head is not automatically expired
        removeLocked(soonest);
      } else {
        Entry<K, V> lru = entries.values().iterator().next();   // eldest in access order
        removeLocked(lru);                       // an in-flight victim still completes for its waiters
      }
    }
  }
}
```

Notes on the code:
- `entries.get` in the completion reorders the entry to most-recent. That is fine: a just-loaded value is the most recently used.
- If the LRU victim is an in-flight load, its waiters still get the value; the completion sees `current == false` and does not index it. Eviction never leaves a half-entry behind.
- `put` during an in-flight load: the new entry replaces the placeholder; callers already waiting on the old future get the loaded (older) value, new callers get the put value. If that matters, complete the old future with the put value instead.
- The loader's future may complete on a DB driver thread; the completion does only O(log n) work under the lock, so it does not stall that thread.

## 6. Tests

Fake `Clock` (settable millis) and a fake `Loader` that counts calls and returns futures the test completes by hand, so nothing sleeps.

Functional:
- Miss then hit: one load, both `get`s return the value.
- TTL: put with 10 s TTL at t=0; `get` at 9 999 ms hits, at 10 000 ms reloads (boundary of `>=`).
- Per-entry TTL: A with 5 s, B with 60 s; at 6 s A reloads, B hits.
- LRU: capacity 2; put A, put B, get A, put C -> B evicted, A and C remain.
- Expired before LRU: capacity 2; A (TTL 1 s), B (TTL 60 s), get A at 0.5 s so B is LRU; at 2 s put C -> A (expired) is dropped, B stays.
- Overwrite: `put` twice on one key leaves one entry in each index (check index sizes equal map size).
- Failed load: first `get` fails; next `get` calls the loader again and succeeds.
- Put beats an older load: start a load for K, `put(K, v2)`, then complete the load with v1; a later `get(K)` returns v2.
- `invalidate` during a load: the completed load is not cached.
- A caller cancelling its returned future does not cancel the others.

Concurrency:
- 100 threads `get` one missing key behind a start latch; complete the load once: exactly 1 loader call, all 100 futures yield the same value.
- Randomised stress: 32 threads, random `get/put/invalidate` over 1 000 keys with capacity 100 and a fake clock advanced by another thread; afterwards assert `entries.size() <= capacity` and that the set of loaded keys equals the keys in `byExpiry`. Run repeatedly in CI.
- A loader that never completes for key A does not block `get` on key B (the lock is not held during loads).

## 7. Next likely requirements

- **Write-through:** `cache.put` becomes `db.save(k, v).thenRun(() -> cache.put(k, v, ttl))`; memory is updated only after the DB accepts the write.
- **LFU instead of LRU:** replace the access-ordered `LinkedHashMap` eviction with a third index ordered by `(accessCount, lastAccess)`; the cache body calls one `victim()` method so the policy is a constructor-injected comparator, not an `if` inside the cache.
- **Refresh-ahead / stale-while-revalidate:** serve the expired value and trigger one background load using the same in-flight-future slot.
- **Metrics:** hit, miss, load, evict events emitted from the same insert/remove choke points.
