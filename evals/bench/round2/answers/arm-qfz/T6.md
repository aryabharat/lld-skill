# T6 In-process cache: TTL + LRU + concurrency + slow loader

## First: do you need to write it?
In production I would use Caffeine (`maximumSize`, `expireAfterWrite`/`Expiry` for per-entry TTL, `LoadingCache` gives single-flight loads). It is what a hand-written version converges to, with better hit rates (W-TinyLFU) and less lock contention. Below is the core if we must own it (interview, or no dependency allowed).

## Requirements -> decisions
| Requirement | Decision |
|---|---|
| LRU at fixed capacity | `LinkedHashMap` in access order; evict eldest on insert over capacity. O(1). |
| Per-entry TTL | Each entry stores `expiresAtNanos`; checked on read (lazy expiry). Expired entries also get evicted by LRU over time; optional sweeper for memory. |
| Many threads `get`/`put` | One `ReentrantLock` guards the map. Critical sections are O(1) pointer updates (a `get` in access-order *mutates* the list, so a read-write lock would not help). |
| `load(key)` ~50 ms | **Never call `load` while holding the lock.** Otherwise every thread waits 50 ms behind one miss. |
| Thundering herd on a miss | Single-flight: concurrent misses on the same key share one `CompletableFuture`; one DB call, not 100. |
| Stale load racing a `put` | A `put` while a load is in flight wins; the loader only installs its value if its future is still the registered one. |

Why not `ConcurrentHashMap` + separate LRU list: two structures that must stay consistent need a lock anyway; the single lock is simpler and correct, and an O(1) lock hold is cheap. If profiling shows contention, shard: N independent segments by `hash(key) % N`, each with its own lock and capacity/N (LRU becomes approximate per segment, which is usually fine).

## Code

```java
public final class LruTtlCache<K, V> {

    private record Entry<V>(V value, long expiresAtNanos) {
        boolean expired(long now) { return now - expiresAtNanos >= 0; }
    }

    private final int capacity;
    private final Duration defaultTtl;
    private final Function<K, V> loader;          // the slow DB call
    private final Executor loadExecutor;          // bounded pool for DB loads
    private final LongSupplier nanoClock;         // System::nanoTime in prod, fake in tests

    private final ReentrantLock lock = new ReentrantLock();
    private final LinkedHashMap<K, Entry<V>> map;                  // guarded by lock
    private final ConcurrentHashMap<K, CompletableFuture<V>> inflight = new ConcurrentHashMap<>();

    public LruTtlCache(int capacity, Duration defaultTtl, Function<K, V> loader,
                       Executor loadExecutor, LongSupplier nanoClock) {
        this.capacity = capacity; this.defaultTtl = defaultTtl; this.loader = loader;
        this.loadExecutor = loadExecutor; this.nanoClock = nanoClock;
        this.map = new LinkedHashMap<>(16, 0.75f, true) {              // access order = LRU
            @Override protected boolean removeEldestEntry(Map.Entry<K, Entry<V>> e) {
                return size() > LruTtlCache.this.capacity;
            }
        };
    }

    /** Cached value if present and fresh; otherwise loads (single-flight). */
    public V get(K key) {
        V hit = getIfPresent(key);
        if (hit != null) return hit;
        return join(loadOnce(key));
    }

    public V getIfPresent(K key) {
        long now = nanoClock.getAsLong();
        lock.lock();
        try {
            Entry<V> e = map.get(key);                 // also moves key to MRU
            if (e == null) return null;
            if (e.expired(now)) { map.remove(key); return null; }
            return e.value();
        } finally { lock.unlock(); }
    }

    public void put(K key, V value) { put(key, value, defaultTtl); }

    public void put(K key, V value, Duration ttl) {
        Objects.requireNonNull(value);
        inflight.remove(key);                          // any in-flight load is now stale: it must not overwrite us
        install(key, value, ttl);
    }

    public void invalidate(K key) {
        inflight.remove(key);
        lock.lock();
        try { map.remove(key); } finally { lock.unlock(); }
    }

    // ---------- internals ----------

    private CompletableFuture<V> loadOnce(K key) {
        CompletableFuture<V> mine = new CompletableFuture<>();
        CompletableFuture<V> existing = inflight.putIfAbsent(key, mine);
        if (existing != null) return existing;         // someone is already loading: wait on theirs

        // re-check: a put may have landed between our miss and registering the future
        V raced = getIfPresent(key);
        if (raced != null) { inflight.remove(key, mine); mine.complete(raced); return mine; }

        loadExecutor.execute(() -> {
            try {
                V v = loader.apply(key);               // ~50 ms, no lock held
                if (v != null && inflight.remove(key, mine)) {   // still the current load? then install
                    install(key, v, defaultTtl);
                } else {
                    inflight.remove(key, mine);
                }
                mine.complete(v);
            } catch (Throwable t) {
                inflight.remove(key, mine);            // failures are not cached; next get retries
                mine.completeExceptionally(t);
            }
        });
        return mine;
    }

    private void install(K key, V value, Duration ttl) {
        long expires = nanoClock.getAsLong() + ttl.toNanos();
        lock.lock();
        try { map.put(key, new Entry<>(value, expires)); }   // removeEldestEntry enforces capacity
        finally { lock.unlock(); }
    }

    private static <V> V join(CompletableFuture<V> f) {
        try { return f.get(2, TimeUnit.SECONDS); }      // bound the wait; DB hang must not hang request threads forever
        catch (ExecutionException e) { throw new CacheLoadException(e.getCause()); }
        catch (TimeoutException e) { throw new CacheLoadException(e); }
        catch (InterruptedException e) { Thread.currentThread().interrupt(); throw new CacheLoadException(e); }
    }
}
```

## Concurrency walkthrough
- **Lock scope**: only `LinkedHashMap` reads/writes, all O(1). No I/O, no callbacks, no `loader` call under the lock.
- **Hit path**: one lock acquire, MRU bump, expiry check.
- **Miss, 100 threads same key**: first `putIfAbsent` wins and starts one DB load; the other 99 get the same future and block on it (bounded by timeout). One DB call.
- **Miss, different keys**: loads run in parallel on `loadExecutor`; the executor size is the cap on concurrent DB calls (back-pressure for the DB).
- **put vs in-flight load**: `put` removes the in-flight future first, so the loader's `inflight.remove(key, mine)` fails and it does not install the older DB value. Waiters on that future still get the loaded value (slightly older than the put, acceptable for that one request).
- **Expiry**: lazy on read with a monotonic clock (`nanoTime`, not wall-clock, so NTP jumps do not expire or resurrect entries). Expired-but-unread entries hold memory until LRU pushes them out; add a periodic sweep (`map.values().removeIf(expired)` under the lock, in batches) if TTLs are short and capacity large.
- **Null / missing rows**: not cached here (loader returns null -> not installed). If "row does not exist" is frequent, cache a sentinel with a short TTL to protect the DB.

## Optional improvements (when measurements say so)
- Lock striping / segments for contention.
- Refresh-ahead: when an entry is within X% of its TTL, serve it and trigger an async reload, so hot keys never miss.
- Jitter on TTL to avoid many keys expiring together.
- Metrics: hit rate, load latency, evictions, in-flight count.

## Tests
- Capacity: insert cap+1 -> eldest gone; after `get(a)`, inserting evicts `b` not `a` (LRU order).
- TTL: fake clock; entry visible before expiry, gone at exactly `expiresAt`; per-entry TTL overrides default.
- Single-flight: loader that counts calls and blocks on a latch; 50 threads `get(k)` -> loader called once, all receive the value.
- Load failure: exception propagates to all waiters, nothing cached, next `get` calls loader again.
- `put` during in-flight load: loader blocked, `put(k, new)`, release loader -> `getIfPresent(k) == new`.
- Hit path does not wait on a slow load of a different key (loader for `x` blocked; `get(y)` returns immediately).
- Stress: many threads random get/put/invalidate; invariant `size <= capacity` always, no exceptions.
