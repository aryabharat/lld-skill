# T7 Schema: organisations, members, teams, repositories, access grants

PostgreSQL. Assumptions: repositories are owned by organisations only (user-owned repos are out of scope); teams belong to one organisation; a team can only be granted access to repos of its own organisation; org admins implicitly have admin on every repo of their org; permissions are ordered `read < triage < write < maintain < admin`.

## Tables

```sql
CREATE TABLE users (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    login       text        NOT NULL,
    email       text        NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX users_login_uq ON users (lower(login));     -- logins are case-insensitive
CREATE UNIQUE INDEX users_email_uq ON users (lower(email));

CREATE TABLE organizations (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    login       text        NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX organizations_login_uq ON organizations (lower(login));

CREATE TYPE org_role AS ENUM ('member', 'admin');

CREATE TABLE org_memberships (
    org_id      bigint   NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    user_id     bigint   NOT NULL REFERENCES users(id)         ON DELETE CASCADE,
    role        org_role NOT NULL DEFAULT 'member',
    created_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (org_id, user_id)                 -- "members of org X", and one role per user per org
);
CREATE INDEX org_memberships_user_idx ON org_memberships (user_id);   -- "orgs of user Y"

CREATE TABLE teams (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    org_id      bigint NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    name        text   NOT NULL,
    UNIQUE (org_id, id)                           -- target for composite FKs below
);
CREATE UNIQUE INDEX teams_org_name_uq ON teams (org_id, lower(name));

CREATE TABLE team_members (
    team_id     bigint NOT NULL,
    org_id      bigint NOT NULL,
    user_id     bigint NOT NULL,
    PRIMARY KEY (team_id, user_id),
    FOREIGN KEY (org_id, team_id) REFERENCES teams (org_id, id)                       ON DELETE CASCADE,
    FOREIGN KEY (org_id, user_id) REFERENCES org_memberships (org_id, user_id)       ON DELETE CASCADE
        -- a team member must be a member of the team's org; leaving the org removes team memberships
);
CREATE INDEX team_members_user_idx ON team_members (user_id);        -- "teams of user Y" (access check)

CREATE TYPE repo_visibility AS ENUM ('public', 'internal', 'private');

CREATE TABLE repositories (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    org_id      bigint NOT NULL REFERENCES organizations(id) ON DELETE RESTRICT,  -- deleting an org with repos is a deliberate act
    name        text   NOT NULL,
    visibility  repo_visibility NOT NULL DEFAULT 'private',
    created_at  timestamptz NOT NULL DEFAULT now(),
    UNIQUE (org_id, id)
);
CREATE UNIQUE INDEX repositories_org_name_uq ON repositories (org_id, lower(name));  -- URL lookup org/repo, also "repos of org"

-- permission as smallint so "highest grant" is a MAX(); 1=read 2=triage 3=write 4=maintain 5=admin
CREATE TABLE repo_user_grants (
    repo_id     bigint   NOT NULL REFERENCES repositories(id) ON DELETE CASCADE,
    user_id     bigint   NOT NULL REFERENCES users(id)        ON DELETE CASCADE,
    permission  smallint NOT NULL CHECK (permission BETWEEN 1 AND 5),
    granted_by  bigint   REFERENCES users(id) ON DELETE SET NULL,
    granted_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (repo_id, user_id)                -- one direct grant per user per repo; "who has access to repo R"
);
CREATE INDEX repo_user_grants_user_idx ON repo_user_grants (user_id, repo_id);   -- "repos user Y can see"

CREATE TABLE repo_team_grants (
    repo_id     bigint   NOT NULL,
    team_id     bigint   NOT NULL,
    org_id      bigint   NOT NULL,
    permission  smallint NOT NULL CHECK (permission BETWEEN 1 AND 5),
    granted_by  bigint   REFERENCES users(id) ON DELETE SET NULL,
    granted_at  timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (repo_id, team_id),
    FOREIGN KEY (org_id, repo_id) REFERENCES repositories (org_id, id) ON DELETE CASCADE,
    FOREIGN KEY (org_id, team_id) REFERENCES teams        (org_id, id) ON DELETE CASCADE
        -- same org_id in both FKs: the DB rejects granting org A's team access to org B's repo
);
CREATE INDEX repo_team_grants_team_idx ON repo_team_grants (team_id, repo_id);   -- "repos of team T" and access check
```

## Key choices and why
- **Two grant tables, not one polymorphic `(grantee_type, grantee_id)` table.** Polymorphic ids cannot have foreign keys, so deleted users/teams leave orphan grants. Two tables keep real FKs and cascading deletes. (Alternative with the same integrity: one table with nullable `user_id` and `team_id` + `CHECK (num_nonnulls(user_id, team_id) = 1)` and two partial unique indexes; fine too, slightly harder to index.)
- **Composite FKs carrying `org_id`** enforce cross-org rules in the database instead of trusting application code: team grant must be same-org; team member must be an org member.
- **Org role on the membership row**, not a separate admins table: a user is exactly one of member/admin per org, enforced by the PK.
- **Org admin -> repo admin is derived, not stored.** Storing it would need fan-out writes on every repo creation and every role change.
- **Surrogate `bigint` ids** so renames (org/repo/user login changes, common on GitHub) do not rewrite FKs; case-insensitive unique indexes on names.
- **`ON DELETE`**: memberships and grants cascade; repositories `RESTRICT` the org delete so it is an explicit, audited operation.

## Index rationale (by query)
| Query | Served by |
|---|---|
| Resolve `org/repo` from URL | `repositories_org_name_uq (org_id, lower(name))` after `organizations_login_uq` |
| Members of org / is user in org | PK `org_memberships (org_id, user_id)` |
| Orgs of a user (dashboard) | `org_memberships_user_idx (user_id)` |
| Effective permission of user U on repo R (hot path, every request) | `repo_user_grants` PK `(repo_id, user_id)`; `team_members_user_idx` + `repo_team_grants` PK `(repo_id, team_id)`; `org_memberships` PK |
| Repos user U can access (listing) | `repo_user_grants_user_idx`, `team_members_user_idx` -> `repo_team_grants_team_idx`, `org_memberships_user_idx` -> repos by org |
| Collaborators of repo R (settings page) | grant table PKs lead with `repo_id` |
| Repos of org (org page) | `repositories_org_name_uq` (leading `org_id`) |

FK columns that do not lead an index get one (e.g. `team_members (user_id)`, grant tables' second column), otherwise deleting a user/team does a sequential scan of the child tables.

## Effective permission query

```sql
SELECT MAX(p) AS permission FROM (
    SELECT g.permission AS p
      FROM repo_user_grants g
     WHERE g.repo_id = $repo AND g.user_id = $user
  UNION ALL
    SELECT g.permission
      FROM team_members tm
      JOIN repo_team_grants g ON g.team_id = tm.team_id AND g.repo_id = $repo
     WHERE tm.user_id = $user
  UNION ALL
    SELECT 5                                          -- org admin
      FROM repositories r
      JOIN org_memberships m ON m.org_id = r.org_id AND m.user_id = $user AND m.role = 'admin'
     WHERE r.id = $repo
  UNION ALL
    SELECT 1                                          -- public, or internal + org member
      FROM repositories r
     WHERE r.id = $repo
       AND (r.visibility = 'public'
            OR (r.visibility = 'internal'
                AND EXISTS (SELECT 1 FROM org_memberships m WHERE m.org_id = r.org_id AND m.user_id = $user)))
) x;
```
Every branch is an index lookup; NULL means no access. If this becomes the top query, cache the result per (user, repo) with invalidation on grant/membership changes; I would not denormalise into a materialised "effective access" table until measured.

## Not modelled (would add when needed)
Nested teams (`teams.parent_team_id` + recursive CTE), outside collaborators, pending invitations table, audit log of grant changes, user-owned repositories (an `owner_type` or a personal "org" per user).
