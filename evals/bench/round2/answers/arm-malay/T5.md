# T5 Review: `NotificationService`

Line numbers count from `public class NotificationService {` as L1; the test starts at L21.

## Findings

Races first (wrong today under request threads), then the shape that the next change pays for, then tests.

- `NotificationService.java:L2: race: a static HashMap is read (L5, L10, L15) and written (L7, L12, L17) by concurrent request threads. HashMap is not thread-safe: concurrent puts can lose entries or corrupt a bucket during resize, and reads can miss writes. Use a ConcurrentHashMap.`
- `NotificationService.java:L5: race: check-then-act in two steps. Two requests for the same user both read the old timestamp at L5, both pass, both send at L6, and only then write L7. The throttle fails exactly under the burst it exists for, and the window widens with the latency of the send. Claim the slot atomically before sending (compute on a ConcurrentHashMap), and give it back if the send fails.`
- `NotificationService.java:L14: variant: third copy of the same throttle-send-record block (L4, L9), differing only in the client and the address. The next fix (the race above) has to go into three places. One private method that takes the channel; each public method is one line.`
- `NotificationService.java:L5: contract: a throttled call returns silently, so a caller (and the request that triggered it) cannot tell "sent" from "dropped". Return a result (SENT / THROTTLED), or a boolean if no caller needs more.`
- `NotificationService.java:L2: owner: one key per user across all channels: an email at t=0 silently drops an SMS at t=5s. If the rule is "one notification per user per minute on any channel", say so in a comment; if it is per channel, key by (userId, channel). Needs a product answer.`
- `NotificationService.java:L2: owner: static state on an instance service. Every instance and every test shares one map, so tests leak into each other by run order. Make it an instance field and let the DI container hold one instance.`
- `NotificationService.java:L2: memory: the map gains one entry per user forever. Remove entries older than the window (or use a cache with expire-after-write, e.g. Caffeine with a 60 s TTL).`
- `NotificationService.java:L22: test: the service reads System.currentTimeMillis (L5, L7), so no test can check that sending works again after 60 s without sleeping. Inject a clock (java.time.Clock or LongSupplier) and move it in the test.`
- `NotificationService.java:L21: test: the only test is single-threaded, so it stays green with both races above. Add a concurrent test: N threads send to one user at once, exactly one send reaches the fake. Confirm it fails against the current code.`

## Suggested shape

```java
public class NotificationService {
    private static final long WINDOW_MS = 60_000;

    public enum Outcome { SENT, THROTTLED }

    private final ConcurrentHashMap<String, Long> lastSent = new ConcurrentHashMap<>();  // throttle key -> epoch ms
    private final LongSupplier clock;
    private final EmailClient emailClient;
    private final SmsClient smsClient;
    private final PushClient pushClient;

    public Outcome sendEmail(User u, String msg) { return send(u, () -> emailClient.send(u.getEmail(), msg)); }
    public Outcome sendSms(User u, String msg)   { return send(u, () -> smsClient.send(u.getPhone(), msg)); }
    public Outcome sendPush(User u, String msg)  { return send(u, () -> pushClient.send(u.getDeviceToken(), msg)); }

    private Outcome send(User u, Runnable delivery) {
        String key = u.getId();                       // or u.getId() + ":" + channel, per the product answer
        long now = clock.getAsLong();                 // read once
        if (!tryAcquire(key, now)) return Outcome.THROTTLED;
        try {
            delivery.run();
            return Outcome.SENT;
        } catch (RuntimeException e) {
            lastSent.remove(key, now);                // give the slot back only if it is still ours
            throw e;
        }
    }

    /** Atomic: of N concurrent callers for one key inside the window, exactly one gets true. */
    private boolean tryAcquire(String key, long now) {
        boolean[] acquired = {false};
        lastSent.compute(key, (k, prev) -> {
            if (prev == null || now - prev >= WINDOW_MS) { acquired[0] = true; return now; }
            return prev;
        });
        return acquired[0];
    }
}
```
