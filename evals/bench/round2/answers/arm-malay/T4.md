# T4 Order status: State pattern?

## Short answer

Not the full State pattern. Your states differ only in **which transitions are allowed**; nothing in the request says a COOKING order behaves differently from a CONFIRMED one for any other operation. A State class per status would hold one method each (`next()` / `cancel()`), and five or six classes would encode what a table of ten lines says. Use an enum that owns its transition table, one method on `Order` that checks and changes the status, and one notification point after each change.

The transition graph is clear and sparse (each state names its successors without any other input), which is the condition under which State classes do work. So switch when states start to carry **different behaviour**, not just different arrows: for example, cancel from COOKING charges a fee and needs restaurant approval, while cancel from PLACED refunds in full. Then each state class has real code and the switch is worth it.

## Design

```java
enum OrderStatus {
    PLACED, CONFIRMED, COOKING, PICKED, DELIVERED, CANCELLED;

    private static final Map<OrderStatus, Set<OrderStatus>> NEXT = new EnumMap<>(Map.of(
        PLACED,    EnumSet.of(CONFIRMED, CANCELLED),
        CONFIRMED, EnumSet.of(COOKING, CANCELLED),
        COOKING,   EnumSet.of(PICKED, CANCELLED),
        PICKED,    EnumSet.of(DELIVERED),
        DELIVERED, EnumSet.noneOf(OrderStatus.class),
        CANCELLED, EnumSet.noneOf(OrderStatus.class)));

    boolean canMoveTo(OrderStatus target) { return NEXT.get(this).contains(target); }
    boolean isTerminal() { return NEXT.get(this).isEmpty(); }
}

record StatusChanged(String orderId, OrderStatus from, OrderStatus to, Instant at, String reason) {}

class IllegalTransitionException extends RuntimeException {
    IllegalTransitionException(String orderId, OrderStatus from, OrderStatus to) {
        super("order " + orderId + ": cannot move " + from + " -> " + to);
    }
}

class Order {
    private final String id;
    private OrderStatus status = OrderStatus.PLACED;

    Order(String id) { this.id = id; }

    /** The only write to status. Checks the transition, then changes it. */
    StatusChanged moveTo(OrderStatus target, Instant at, String reason) {
        if (!status.canMoveTo(target)) throw new IllegalTransitionException(id, status, target);
        StatusChanged event = new StatusChanged(id, status, target, at, reason);
        status = target;
        return event;
    }

    OrderStatus status() { return status; }
}
```

Intent-named methods keep callers from passing arbitrary targets where it matters:

```java
class OrderService {
    private final OrderRepository orders;
    private final OrderStatusListeners listeners;
    private final Clock clock;

    void confirm(String id)            { change(id, OrderStatus.CONFIRMED, null); }
    void startCooking(String id)       { change(id, OrderStatus.COOKING, null); }
    void markPicked(String id)         { change(id, OrderStatus.PICKED, null); }
    void markDelivered(String id)      { change(id, OrderStatus.DELIVERED, null); }
    void cancel(String id, String why) { change(id, OrderStatus.CANCELLED, why); }

    private void change(String id, OrderStatus target, String reason) {
        Order order = orders.get(id);
        OrderStatus expected = order.status();
        StatusChanged event = order.moveTo(target, clock.instant(), reason);
        // Compare-and-set in the store: UPDATE orders SET status=:to WHERE id=:id AND status=:from
        // Two racing requests (customer cancels while the rider picks up): exactly one wins, the other
        // gets a conflict and re-reads.
        if (!orders.saveIfStatus(order, expected)) throw new ConcurrentModificationException("order " + id + " changed");
        listeners.publish(event);   // after the save: never notify about a change that did not persist
    }
}
```

## Notifications

Every change reaches the customer and the restaurant, and the request names analytics as a third consumer. With three consumers of one event, `OrderService` should not call each one; it calls one publisher, and the consumers are wired in one place:

```java
interface OrderStatusListener { void onStatusChanged(StatusChanged e); }

final class OrderStatusListeners {
    private final List<OrderStatusListener> listeners;
    OrderStatusListeners(List<OrderStatusListener> listeners) { this.listeners = List.copyOf(listeners); }

    void publish(StatusChanged e) {
        for (OrderStatusListener l : listeners) {
            try { l.onStatusChanged(e); }
            catch (RuntimeException ex) { log.warn("listener {} failed for {}", l, e, ex); }  // one failure does not stop the rest
        }
    }
}

// wiring, one line per consumer
new OrderStatusListeners(List.of(
    customerNotifier,      // maps StatusChanged -> push/SMS text for the customer
    restaurantNotifier     // maps StatusChanged -> restaurant dashboard update
    // , analyticsRecorder  // when analytics subscribes
));
```

Each consumer turns the event into its own message (the customer does not need to hear about CONFIRMED -> COOKING in the same words as the restaurant); the event carries no "to email" or "to SMS" logic. Listeners are fixed at startup, so there is no runtime `subscribe`/`unsubscribe`.

`ponytail: synchronous, in-process delivery; a slow or down notifier delays the request. Move to an outbox table + async worker when a notifier must not block the status change or must not lose an event on a crash.`

## Tests

- Every allowed transition succeeds, and every pair not in the table throws `IllegalTransitionException` (loop over all 36 pairs and compare with the table, so the table and the test cannot drift silently).
- Cancel works from PLACED, CONFIRMED and COOKING, and fails from PICKED, DELIVERED and CANCELLED.
- A successful change publishes exactly one `StatusChanged` with the right `from`/`to`, to every listener (fake listeners that record events).
- A failed transition publishes nothing; a failed save publishes nothing.
- A listener that throws does not stop the next listener.
- Clock is injected; `at` equals the fixed test instant.
