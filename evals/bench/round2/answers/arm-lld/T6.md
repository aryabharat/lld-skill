# In-process loading cache: per-entry TTL, LRU, concurrent

## Assumptions

- `load(key)` is a blocking DB call that takes about 50 ms. It must never run while holding the cache lock, and it must never run on the caller's request thread.
- `put(k, v, ttl)` is cache-aside: the caller has already written the DB, and the cache just stores the new value. Write-through would wrap `put` around `persist(k, v).thenApply(x -> v)`.
- TTL counts from when the value enters the cache, not from the last access.
- In-flight loads count toward capacity.
- Consistency: a `put` wins over a load that was already in flight for the same key. A caller who issued `get` before that `put` may still receive the older DB value.

## API

```java
CompletableFuture<V> get(K key);                 // hit: completed future; miss: one shared load
void put(K key, V value, Duration ttl);
void invalidate(K key);
```

`get` returns a future because a miss means IO. A caller that truly needs a synchronous value can join it with a timeout on its own thread.

## Data structures

| Structure | Purpose | Cost |
|---|---|---|
| `LinkedHashMap<K, Node<V>>` (access-order) | lookup + LRU order; eldest = victim | O(1) get/put/evict |
| `TreeSet<Node<V>>` by `(expiresAt, seq)` | expiry index: earliest-expiring first | O(log n) add/remove/first |
| `Node{key, CompletableFuture<V> value, long expiresAt, long seq}` | the in-flight future gives request collapsing | - |

Expiry and recency are two independent orders, so they need two indexes. A single index cannot answer both "oldest by TTL" and "least recently used". Only loaded nodes enter the expiry index, so its sort key is set once and never mutated while indexed.

## Concurrency

- **One lock over the composite.** The map and the expiry set must change together, so a concurrent collection per part would still allow torn states (a key evicted from the map but still in the index). An access-ordered `LinkedHashMap` also mutates on `get`, so even reads need the exclusive lock, and a read-write lock would not help.
- **The lock covers only O(log n) bookkeeping.** It is never held during `load()`. It is also never held while completing a future, because completion runs callers' callbacks, which could re-enter the cache or be slow.
- **Request collapsing.** The first miss inserts a node holding an incomplete future, and later `get`s for that key return the same future. A thousand concurrent misses on a hot key cost one DB call.
- **Loads run on a bounded `loadPool`** with a timeout. Request threads only ever touch the lock briefly.
- **Stale-load race.** A load completes after a `put` or `invalidate` replaced its node. The completion callback checks node identity (`entries.get(key) == node`) and does not install the stale value.
- **Failed loads are removed,** so the next `get` retries instead of serving a cached exception.
- **Scaling.** If profiling shows contention on the single lock, split the cache into 16 segments by `floorMod(hash, 16)`, each with its own lock and capacity/16. LRU then becomes approximate per segment. In production, use Caffeine, which does exactly this, better.

## Code

```java
public final class LoadingCache<K, V> {
  private static final class Node<V> {
    final Object key; final long seq; final CompletableFuture<V> value;
    long expiresAt = Long.MAX_VALUE;                        // set once, when loaded, under lock
    Node(Object key, long seq, CompletableFuture<V> value) { this.key = key; this.seq = seq; this.value = value; }
    boolean loaded()            { return expiresAt != Long.MAX_VALUE; }
    boolean expired(long now)   { return loaded() && now >= expiresAt; }
  }

  private final int capacity; private final long defaultTtlMs;
  private final Function<K, V> loader; private final Executor loadPool; private final Clock clock;
  private final ReentrantLock lock = new ReentrantLock();
  private final LinkedHashMap<K, Node<V>> entries = new LinkedHashMap<>(16, 0.75f, true);
  private final TreeSet<Node<V>> byExpiry = new TreeSet<>(
      Comparator.<Node<V>>comparingLong(n -> n.expiresAt).thenComparingLong(n -> n.seq));
  private long seq;

  public CompletableFuture<V> get(K key) {
    long now = clock.millis();                              // read once
    Node<V> node; boolean mustLoad = false;
    lock.lock();
    try {
      node = entries.get(key);                              // also marks most-recently-used
      if (node != null && node.expired(now)) { removeLocked(key, node); node = null; }
      if (node == null) {
        makeRoomLocked(now);
        node = new Node<>(key, seq++, new CompletableFuture<>());
        entries.put(key, node);                             // placeholder visible to other callers
        mustLoad = true;
      }
    } finally { lock.unlock(); }
    if (mustLoad) startLoad(key, node);                     // outside the lock
    return node.value;
  }

  public void put(K key, V value, Duration ttl) {
    long now = clock.millis();
    lock.lock();
    try {
      Node<V> old = entries.remove(key);
      if (old != null) byExpiry.remove(old);
      makeRoomLocked(now);
      Node<V> n = new Node<>(key, seq++, CompletableFuture.completedFuture(value));
      n.expiresAt = now + ttl.toMillis();
      entries.put(key, n); byExpiry.add(n);
    } finally { lock.unlock(); }
  }

  public void invalidate(K key) {
    lock.lock();
    try { Node<V> n = entries.remove(key); if (n != null) byExpiry.remove(n); }
    finally { lock.unlock(); }
  }

  private void startLoad(K key, Node<V> node) {
    CompletableFuture.supplyAsync(() -> loader.apply(key), loadPool)   // sync throw -> failed future
        .orTimeout(2, TimeUnit.SECONDS)
        .whenComplete((v, err) -> {
          lock.lock();
          try {
            boolean current = entries.get(key) == node;               // replaced or evicted meanwhile?
            if (current && err != null) entries.remove(key);          // do not cache failures
            else if (current) { node.expiresAt = clock.millis() + defaultTtlMs; byExpiry.add(node); }
          } finally { lock.unlock(); }
          if (err != null) node.value.completeExceptionally(err);     // complete outside the lock
          else node.value.complete(v);
        });
  }

  private void makeRoomLocked(long now) {
    while (entries.size() >= capacity) {
      Node<V> soonest = byExpiry.isEmpty() ? null : byExpiry.first();
      if (soonest != null && soonest.expired(now)) {                  // drop expired before live
        removeLocked((K) soonest.key, soonest);
      } else {
        Map.Entry<K, Node<V>> eldest = entries.entrySet().iterator().next();   // LRU victim
        removeLocked(eldest.getKey(), eldest.getValue());
      }
    }
  }

  private void removeLocked(K key, Node<V> n) {                       // the one removal path
    entries.remove(key, n);
    byExpiry.remove(n);
  }
}
```

Notes on the code:
- Evicting an in-flight node is safe. Its waiters still get the value through their future; it just isn't cached, because the identity check fails.
- `put` and `get` both go through `makeRoomLocked`, and every removal goes through `removeLocked`, so the two indexes cannot drift apart.
- A key that only ever arrives through `put` gets its own TTL. Loaded entries use the default TTL. If the loader should decide the TTL per entry, have it return `Loaded<V>(value, ttl)`.

Per operation:

| Operation | Cost |
|---|---|
| `get` hit | O(1) |
| `get` miss | O(1) under the lock, plus O(log n) on completion, plus one 50 ms load shared by all waiters |
| `put` | O(log n) |
| Eviction | O(log n) |

## Tests

These use a fake `Clock` and a fake loader that counts calls and completes when the test releases it.

1. **Collapsing:** 100 threads `get("a")` while the loader is held. The loader is called exactly once, and all 100 futures complete with the same value.
2. **Non-blocking:** with the loader held, `get` returns an incomplete future within a few ms on the caller thread.
3. **TTL boundary:** `put("a", 1, 10s)` at t=0. At t=9 999 it is a hit. At t=10 000 it is a miss and the loader is called.
4. **LRU:** capacity 2. Put a, put b, get a, put c. Now b is evicted and a and c remain.
5. **Expired before LRU:** capacity 2. Put a (ttl 1s), put b (ttl 1h), get a (a is now most recent), advance 2s, put c. Now a is evicted, not b.
6. **Failed load is not cached:** the loader throws once. The next `get` calls it again and succeeds.
7. **Stale load loses to put:** start the load of "a" (returns 1, held), `put("a", 2)`, release the load. Then `get("a")` returns 2.
8. **Stress invariant:** 32 threads doing random get, put and invalidate on 50 keys with capacity 20. After joining: `entries.size() <= 20`, every node in `byExpiry` is in `entries`, and no future stays incomplete after the loader is released.
