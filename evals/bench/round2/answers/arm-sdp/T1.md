# T1: Parking lot pricing and allocation

## Assumptions
- One process owns the lot (a single JVM serves all gates). If gates were separate services, the allocation step would move to a database row lock or a conditional update; the interface below would not change.
- Fees are computed at exit from entry time, exit time, vehicle type and (later) customer info. Money is `BigDecimal` in a single currency, rounded at the end.
- A vehicle fits a spot of its own size. Letting a bike take a car spot is a policy we can add inside the allocator later without changing callers.
- "Weekend" is judged by the entry day in the lot's time zone. Sessions that cross a weekday/weekend boundary are priced hour by hour (this is cheap to do and avoids an argument later).

## The two modules and why they are split this way

The design has two deep modules with small interfaces. Each hides one set of design decisions:

| Module | Interface callers see | What it hides |
|---|---|---|
| `ParkingLot` | `Optional<Ticket> park(Vehicle)`, `Optional<Receipt> leave(String ticketId)` | floors, spot indexes, locking, ticket storage |
| `Tariff` | `Money price(ParkingSession)` | rates, weekday/weekend, rule ordering, how discounts and surcharges combine |

The gate code knows nothing about floors, locks or rates. I am deliberately not splitting this into `EntryGateService -> SpotFinder -> SpotReserver -> TicketIssuer` because that is temporal decomposition: each step would need to know the spot data structure, and the lock would leak across all of them.

## Pricing: one Tariff, rules inside it

Product says night rate, member discount and event surcharge are coming. These rules are not all the same kind:
- base rate (per vehicle type, per day type) produces the starting amount,
- night rate changes the rate for some hours,
- event surcharge adds an amount,
- member discount takes a percentage off the total.

If every rule is a generic `PricingRule` in a flat list, the ordering ("discount after surcharge?") becomes an implicit convention that every new rule author must know. So I make the stages explicit inside the `Tariff` and keep that order in one place.

```java
/** Everything a price can depend on. New inputs (member id, event id) are added here, not to method signatures. */
public record ParkingSession(VehicleType type, Instant entry, Instant exit, Optional<String> memberId) {}

public interface Tariff {
    /** Total fee for a finished session. Never negative; rounded to the currency's minor unit. */
    Money price(ParkingSession session);
}

/** Rate for one hour of parking. Night rate is just another HourlyRate implementation. */
interface HourlyRate {
    /** Returns the rate for the hour that starts at {@code hourStart}, or empty if this rate does not apply. */
    Optional<BigDecimal> rateFor(VehicleType type, ZonedDateTime hourStart);
}

/** Adjustments applied to the subtotal: surcharges first, then discounts. */
interface Adjustment {
    enum Kind { SURCHARGE, DISCOUNT }
    Kind kind();
    /** Returns the adjusted amount. Must not return a negative value. */
    BigDecimal apply(BigDecimal subtotal, ParkingSession session);
}

public final class StandardTariff implements Tariff {
    private final ZoneId zone;
    private final List<HourlyRate> rates;          // first matching rate wins, e.g. [nightRate, baseRate]
    private final List<Adjustment> adjustments;

    public StandardTariff(ZoneId zone, List<HourlyRate> rates, List<Adjustment> adjustments) {
        this.zone = zone;
        if (rates.isEmpty() || !(rates.get(rates.size() - 1) instanceof BaseRate))
            throw new IllegalArgumentException("the last rate must be a BaseRate so every hour has a price");
        this.rates = List.copyOf(rates);
        // Ordering is decided here, once: surcharges, then discounts. Rule authors don't need to know it.
        this.adjustments = adjustments.stream()
            .sorted(Comparator.comparing(Adjustment::kind))
            .toList();
    }

    @Override public Money price(ParkingSession s) {
        BigDecimal subtotal = BigDecimal.ZERO;
        ZonedDateTime hour = s.entry().atZone(zone);
        ZonedDateTime end = s.exit().atZone(zone);
        // Partial hours are charged as a full hour; a session of 0 minutes still pays one hour.
        do {
            subtotal = subtotal.add(rateFor(s.type(), hour));
            hour = hour.plusHours(1);
        } while (hour.isBefore(end));

        for (Adjustment a : adjustments) subtotal = a.apply(subtotal, s);
        return Money.inr(subtotal.max(BigDecimal.ZERO).setScale(2, RoundingMode.HALF_UP));
    }

    private BigDecimal rateFor(VehicleType t, ZonedDateTime hour) {
        for (HourlyRate r : rates) {
            Optional<BigDecimal> rate = r.rateFor(t, hour);
            if (rate.isPresent()) return rate.get();
        }
        // Unreachable: the constructor guarantees a BaseRate last, and BaseRate covers every type.
        throw new AssertionError("no rate for " + t);
    }
}

/** Weekday/weekend base rate: always applies, so it goes last in the rate list. */
final class BaseRate implements HourlyRate {
    private final Map<VehicleType, BigDecimal> weekday, weekend;
    BaseRate(Map<VehicleType, BigDecimal> weekday, Map<VehicleType, BigDecimal> weekend) {
        if (!weekday.keySet().containsAll(EnumSet.allOf(VehicleType.class))
            || !weekend.keySet().containsAll(EnumSet.allOf(VehicleType.class)))
            throw new IllegalArgumentException("base rate must cover every vehicle type");
        this.weekday = Map.copyOf(weekday); this.weekend = Map.copyOf(weekend);
    }
    public Optional<BigDecimal> rateFor(VehicleType t, ZonedDateTime h) {
        DayOfWeek d = h.getDayOfWeek();
        boolean isWeekend = d == DayOfWeek.SATURDAY || d == DayOfWeek.SUNDAY;
        return Optional.of((isWeekend ? weekend : weekday).get(t));
    }
}
```

Adding the coming rules:
- **Night rate**: `new NightRate(22, 6, rates)` implementing `HourlyRate`, placed before `BaseRate`.
- **Event surcharge**: `EventSurcharge(Interval, amount)` as a `SURCHARGE` adjustment.
- **Member discount**: `MemberDiscount(MemberDirectory, percent)` as a `DISCOUNT` adjustment.

None of these change `Tariff`, `ParkingLot` or the gates. The tariff is assembled in one factory (or from config), so "which rules are live" is in one place.

Design-it-twice note: the alternative was a single `List<PricingRule>` where each rule takes and returns a running total. It has a smaller type count but pushes ordering and "is this per hour or per session?" onto every rule author. Two narrow stages are slightly more code inside the module and much less for the people adding rules, which is the better trade.

## Allocation: ParkingLot owns spots and the lock

```java
public final class ParkingLot {
    private final Map<VehicleType, Deque<Spot>> free = new EnumMap<>(VehicleType.class);
    private final Map<String, Ticket> active = new HashMap<>();
    private final Tariff tariff;
    private final Clock clock;
    private final Object lock = new Object();

    public ParkingLot(List<Spot> spots, Tariff tariff, Clock clock) {
        for (VehicleType t : VehicleType.values()) free.put(t, new ArrayDeque<>());
        // Lowest floor first: spots are added in floor order so the deque head is the nearest spot.
        spots.stream().sorted(Comparator.comparingInt(Spot::floor).thenComparing(Spot::id))
             .forEach(s -> free.get(s.size()).addLast(s));
        this.tariff = tariff; this.clock = clock;
    }

    /**
     * Assigns a free spot of the vehicle's size and returns a ticket.
     * Returns empty if the lot is full for that type; "full" is a normal outcome, not an exception.
     * Safe to call from any number of gates at once: two callers never get the same spot.
     */
    public Optional<Ticket> park(Vehicle v) {
        synchronized (lock) {
            Spot spot = free.get(v.type()).pollFirst();
            if (spot == null) return Optional.empty();
            Ticket t = new Ticket(UUID.randomUUID().toString(), v, spot, clock.instant());
            active.put(t.id(), t);
            return Optional.of(t);
        }
    }

    /** Frees the spot and prices the stay. Leaving twice with the same ticket returns empty the second time; the spot goes back to the pool only once. */
    public Optional<Receipt> leave(String ticketId) {
        Ticket t;
        synchronized (lock) {
            t = active.remove(ticketId);
            if (t == null) return Optional.empty();
            free.get(t.spot().size()).addFirst(t.spot());
        }
        Instant exit = clock.instant();
        Money fee = tariff.price(new ParkingSession(t.vehicle().type(), t.entry(), exit, t.vehicle().memberId()));
        return Optional.of(new Receipt(t, exit, fee));
    }
}
```

Concurrency choices:
- **One lock around a pop from a deque.** The critical section is O(1) and has no I/O, so it will not be the bottleneck even with dozens of gates. A per-type lock or `ConcurrentLinkedDeque.pollFirst()` would also work; I keep one lock because `park` updates two structures (`free` and `active`) and they must change together. If contention ever shows up in profiles, switch to `ConcurrentLinkedDeque` per type plus `ConcurrentHashMap` for tickets; the public interface does not change.
- **Pricing runs outside the lock.** It is pure and may later call a member directory.
- **"Lot full" and "unknown ticket" are `Optional.empty()`**, not exceptions. The gate shows "Full" either way; there is nothing to catch.
- **Double exit is idempotent**: the second `leave` finds no ticket and returns empty, so the spot is never added to the pool twice.
- If gates run in separate processes: keep `ParkingLot`'s interface and implement it with `UPDATE spot SET ticket_id=? WHERE id = (SELECT id FROM spot WHERE size=? AND ticket_id IS NULL ORDER BY floor, id LIMIT 1 FOR UPDATE SKIP LOCKED)`.

## Tests

Pricing (pure, fast, use a fixed zone):
1. Car, 2h on a Wednesday = 2 x weekday car rate.
2. Truck on Saturday uses the weekend rate.
3. 61 minutes is charged as 2 hours; 0 minutes is charged as 1 hour.
4. Session from Friday 23:00 to Saturday 01:00 charges one weekday hour and one weekend hour.
5. `BaseRate` constructor rejects a map missing a vehicle type.
6. With a fake `SURCHARGE` and a fake `DISCOUNT` passed in reverse order, the surcharge is still applied first (ordering is the tariff's job).
7. A discount bigger than the subtotal gives 0, never negative.
8. When night rate is added: 21:00 to 23:00 gives one base hour and one night hour (regression for rate precedence).

Allocation:
1. Park a bike, car and truck: each gets a spot of its own size, lowest floor first.
2. Lot with one car spot: second car gets `Optional.empty()`; a bike still parks.
3. `leave` returns the spot; the next car gets that same spot.
4. `leave` twice with the same ticket: second returns empty and the free count goes up by one only.
5. Concurrency: lot with N car spots, 2N threads released together with a `CountDownLatch` all call `park`. Assert exactly N tickets, all spot ids distinct, and N empties. Run it in a loop (e.g. 200 iterations) to make the race likely to show.
6. Concurrent park and leave: threads park and leave in a loop; at the end `free + active == total spots`.
7. `leave` uses an injected `Clock`, so the fee test is deterministic.
