# T6: In-process cache with TTL, LRU and a slow loader

## Assumptions
- Read-through: callers call `get(key)`; on a miss the cache calls `load(key)` (~50 ms). Callers never call the database themselves.
- Capacity is a number of entries, not bytes.
- TTL is per entry: loaded entries get a default TTL, `put` can give its own.
- Values are never null. To cache "row not found", make `V` an `Optional<Row>`.
- In production I would use Caffeine, which does all of this with better concurrency. Below is the core if we must write it.

## Interface

Keep it small. The common path is `get`, and everything hard (locking, expiry, eviction, de-duplicating loads) is hidden behind it.

```java
public interface Cache<K, V> {
    /** Returns the value for key, loading it if absent or expired. Concurrent misses for one key trigger one load. */
    V get(K key);
    /** Stores a value with its own TTL. A load already in flight for this key will not overwrite it. */
    void put(K key, V value, Duration ttl);
    /** Removes the key. Succeeds whether or not it was present. */
    void invalidate(K key);
}
```

## Design decisions (and the alternative I rejected)

| Concern | Choice |
|---|---|
| LRU order + capacity | `LinkedHashMap` in access order, `removeEldestEntry` evicts beyond capacity |
| Map thread safety | one `ReentrantLock` around the `LinkedHashMap`; critical sections are O(1) and do no I/O |
| Slow loader | **never** called while holding the lock |
| Thundering herd (100 threads miss the same key) | `ConcurrentHashMap<K, CompletableFuture<V>>` of in-flight loads: first thread loads, others wait on its future |
| TTL | expiry timestamp stored in each entry, checked on read (lazy); expired entries are also the first to be evicted by LRU since nobody reads them |
| Stale load overwriting a newer `put` | `put`/`invalidate` cancel the in-flight marker under the lock; the loader stores its result only if its marker is still current |
| Time | injected `LongSupplier nanoTime` so TTL tests do not sleep |

Design it twice: the alternative is a `ConcurrentHashMap` for data plus a separate concurrent LRU structure (ring buffer of access events drained under a try-lock, as Caffeine does). It scales better on many cores because reads do not take a lock, but it is much harder to get right. A single lock is enough here: each operation holds it for well under a microsecond, while a miss costs 50 ms, so the lock will not be the bottleneck until hundreds of thousands of hits per second. If profiling says otherwise, switch to Caffeine rather than growing this one.

## Code

```java
public final class LruTtlCache<K, V> implements Cache<K, V> {
    private record Entry<V>(V value, long expiresAtNanos) {}

    private final Function<K, V> loader;
    private final long defaultTtlNanos;
    private final LongSupplier nanoTime;
    private final ReentrantLock lock = new ReentrantLock();
    private final LinkedHashMap<K, Entry<V>> map;                              // guarded by lock
    private final Map<K, CompletableFuture<V>> inFlight = new HashMap<>();     // guarded by lock

    public LruTtlCache(int capacity, Duration defaultTtl, Function<K, V> loader, LongSupplier nanoTime) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be positive");
        this.loader = loader;
        this.defaultTtlNanos = defaultTtl.toNanos();
        this.nanoTime = nanoTime;
        this.map = new LinkedHashMap<>(16, 0.75f, /* accessOrder */ true) {
            @Override protected boolean removeEldestEntry(Map.Entry<K, Entry<V>> eldest) {
                return size() > capacity;
            }
        };
    }

    @Override public V get(K key) {
        CompletableFuture<V> future;
        boolean iLoad = false;

        lock.lock();
        try {
            Entry<V> e = map.get(key);                       // also moves key to most-recent
            if (e != null && nanoTime.getAsLong() < e.expiresAtNanos()) return e.value();
            if (e != null) map.remove(key);                  // expired
            future = inFlight.get(key);
            if (future == null) {
                future = new CompletableFuture<>();
                inFlight.put(key, future);
                iLoad = true;
            }
        } finally {
            lock.unlock();
        }

        if (iLoad) load(key, future);                         // outside the lock: 50 ms of I/O
        return await(future);
    }

    private void load(K key, CompletableFuture<V> marker) {
        try {
            V value = Objects.requireNonNull(loader.apply(key), "loader returned null");
            lock.lock();
            try {
                // Store only if no put/invalidate happened while we were loading.
                if (inFlight.get(key) == marker) {
                    inFlight.remove(key);
                    map.put(key, new Entry<>(value, nanoTime.getAsLong() + defaultTtlNanos));
                }
            } finally {
                lock.unlock();
            }
            marker.complete(value);
        } catch (Throwable t) {
            lock.lock();
            try { inFlight.remove(key, marker); } finally { lock.unlock(); }
            marker.completeExceptionally(t);                  // failures are not cached; next get retries
        }
    }

    @Override public void put(K key, V value, Duration ttl) {
        Objects.requireNonNull(value);
        lock.lock();
        try {
            inFlight.remove(key);                             // an older load must not overwrite this value
            map.put(key, new Entry<>(value, nanoTime.getAsLong() + ttl.toNanos()));
        } finally {
            lock.unlock();
        }
    }

    @Override public void invalidate(K key) {
        lock.lock();
        try {
            inFlight.remove(key);
            map.remove(key);
        } finally {
            lock.unlock();
        }
    }

    private static <V> V await(CompletableFuture<V> f) {
        try {
            return f.join();
        } catch (CompletionException e) {
            Throwable cause = e.getCause();
            if (cause instanceof RuntimeException re) throw re;
            if (cause instanceof Error err) throw err;
            throw new CacheLoadException(cause);
        }
    }
}
```

Notes on the concurrency:
- **Why `inFlight` is under the same lock as `map`**: "is the value present?", "is anyone loading it?" and "register me as the loader" must be one atomic decision. Two separate concurrent maps would leave a window where a thread misses the map just as the loader finishes, and starts a second load.
- **Waiters on a removed marker**: if `put` happens during a load, waiters already holding the old future still get the loaded (slightly older) value. That is the same answer they would have got a few ms earlier; the cache itself keeps the newer `put` value.
- **Failure**: one failed load fails all its current waiters (they asked at the same moment, so the same answer is right), and nothing is cached, so the next `get` retries. If the DB is down, every miss will retry; add a short negative TTL or a circuit breaker in the loader if that becomes a problem.
- **Expired entries**: removed when read, and otherwise naturally fall to the LRU tail. If the TTL is short and capacity matters, add a periodic sweep under the lock; not needed for correctness.
- **Refresh-ahead** (serve the old value while reloading near expiry) is the next thing to add if 50 ms spikes at expiry show up in p99. It fits behind the same `get`.

## Tests
- Miss calls the loader once; hit within TTL does not call it again.
- Advance the fake clock past TTL: next `get` reloads.
- Capacity 2: get A, get B, get A, get C evicts B (not A).
- 100 threads `get` the same missing key at once (latch): loader called exactly once, all get the same value.
- Loader throws: all waiting threads see the exception; next `get` calls the loader again.
- Slow loader for K (blocked on a latch), then `put(K, v2)`, then release the loader: `get(K)` returns v2.
- `invalidate` during a load: the loaded value is not stored.
- Different keys load in parallel (loader for A blocked does not block `get(B)`).
