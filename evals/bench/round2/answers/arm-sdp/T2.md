# T2: Draw after 50 moves without a win

## Assumptions
- "50 moves" means 50 moves in total in this game (both players together). Since any win ends the game, "50 moves without a win" is the same as "the move count has reached 50 and nobody has won".
- The `Board` is the one thing that sees every move, so it is the right place to count them.
- The win checks still take priority: if the 50th move wins, it is a win, not a draw.

## The change

The draw condition belongs to the same question `isFull()` answers: "can play continue?". So I would not add a new `if` with a magic number and a separate counter in `GameEngine`. I would keep the engine reading like the rules, and let the board own its move count.

```java
class Board {
    private int movesPlayed;

    void place(Position p, Player player) {
        // ... existing placement code ...
        movesPlayed++;
    }

    /** Number of moves made so far in this game. */
    int movesPlayed() { return movesPlayed; }

    boolean isFull() { /* unchanged */ }
}
```

```java
class GameEngine {
    /** A game with no winner is drawn once this many moves have been played, even if the board has room. */
    static final int MOVE_LIMIT = 50;

    GameState getState(Board b) {
        if (hasWinningLine(b)) return GameState.win(b.lastPlayer());
        if (b.isFull() || b.movesPlayed() >= MOVE_LIMIT) return GameState.draw();
        return GameState.inProgress();
    }

    private boolean hasWinningLine(Board b) {
        return rowWin(b) || colWin(b) || diagWin(b) || revDiagWin(b);
    }
}
```

Notes on the change:
- The four win checks collapse into `hasWinningLine`. The method now reads as the three outcomes (win, draw, in progress) instead of six steps; the new rule adds one condition, not a seventh branch.
- `>=` rather than `==`: if something ever lets the count pass 50 (undo/redo bug, replays), the game still reports a draw instead of continuing forever.
- If the limit needs to vary by game mode, pass it in the `GameEngine` constructor with 50 as the default. I would not do that until a second value exists.
- If `Board` is shared or immutable and cannot carry a counter, the alternative is to have `GameEngine` count in its `makeMove` method. That is worse because the count and the board can then disagree (e.g. a board loaded from a save), so the counter belongs with the board.

## Tests
- 49 moves, no win, board not full: `inProgress`.
- 50 moves, no win: `draw`.
- The 50th move completes a row: `win`, not `draw` (win precedence).
- Full board before 50 moves (e.g. 3x3 at 9 moves): `draw`, as before.
- Existing row/column/diagonal win tests stay green unchanged.
