# T4 Order status: State pattern or not?

## Short answer
You do need a **state machine**, but not the GoF State pattern with a class per state. The only thing that varies by state here is *which transitions are allowed*. There is no per-state behaviour (pricing, UI, timers) for State classes to hold, so six classes whose only job is to say "next is X, or throw" would be ceremony. An enum plus an explicit transition table gives the same guarantees in one readable place.

The "notify customer and restaurant, analytics may subscribe later" part is a separate concern: that is **Observer** (a list of listeners on the transition event). Keep the two apart: the state machine decides whether a change is legal; the listeners react after it happened.

When I would switch to State classes: when states start carrying their own behaviour, e.g. COOKING has a timeout and an ETA calculation, PICKED tracks the rider, and each state answers `cancel()` with a different refund rule. Then the per-state logic is real and belongs in a class per state.

## Correctness tests (written before the code)
- Happy path: PLACED -> CONFIRMED -> COOKING -> PICKED -> DELIVERED, each step succeeds and the status is updated.
- Cancel is legal from PLACED, CONFIRMED, COOKING (three tests, or one parameterised).
- Illegal transitions throw `IllegalTransitionException` and leave the status unchanged: PLACED -> COOKING (skip), COOKING -> CONFIRMED (backwards), PICKED -> CANCELLED, DELIVERED -> anything, CANCELLED -> anything.
- Same-state transition (CONFIRMED -> CONFIRMED) is rejected, so a retried request is visible instead of firing duplicate notifications. (If the API needs idempotent retries, handle that at the API layer with an idempotency key, not by allowing self-transitions.)
- Invariant: DELIVERED and CANCELLED are terminal; every order ends in exactly one of them.
- Every successful transition notifies each listener exactly once with (orderId, from, to, timestamp); a failed transition notifies nobody.
- A listener that throws does not roll back the transition and does not stop other listeners.
- Adding an analytics listener requires no change to `Order` or the transition table.
- Concurrency: "cancel" and "confirm" racing on the same PLACED order: exactly one succeeds; the other gets `IllegalTransitionException` (or a version conflict when persisted).

## Design

```java
public enum OrderStatus {
    PLACED, CONFIRMED, COOKING, PICKED, DELIVERED, CANCELLED;

    private static final Map<OrderStatus, Set<OrderStatus>> NEXT = new EnumMap<>(Map.of(
        PLACED,    EnumSet.of(CONFIRMED, CANCELLED),
        CONFIRMED, EnumSet.of(COOKING,   CANCELLED),
        COOKING,   EnumSet.of(PICKED,    CANCELLED),
        PICKED,    EnumSet.of(DELIVERED),
        DELIVERED, EnumSet.noneOf(OrderStatus.class),
        CANCELLED, EnumSet.noneOf(OrderStatus.class)));

    public boolean canMoveTo(OrderStatus to) { return NEXT.get(this).contains(to); }
    public boolean isTerminal()             { return NEXT.get(this).isEmpty(); }
}

public record StatusChanged(String orderId, OrderStatus from, OrderStatus to, Instant at) {}

public interface OrderStatusListener {
    void onStatusChanged(StatusChanged event);
}

public final class IllegalTransitionException extends RuntimeException {
    public IllegalTransitionException(String id, OrderStatus from, OrderStatus to) {
        super("order " + id + ": " + from + " -> " + to + " not allowed");
    }
}
```

The `Order` owns its status and is the only place it changes (Tell, Don't Ask: callers say `order.confirm()`, they never set a status field):

```java
public final class Order {
    private final String id;
    private OrderStatus status = OrderStatus.PLACED;
    private long version;                                   // for optimistic locking when persisted

    public Order(String id) { this.id = id; }

    public StatusChanged confirm()   { return moveTo(OrderStatus.CONFIRMED); }
    public StatusChanged startCooking() { return moveTo(OrderStatus.COOKING); }
    public StatusChanged pickUp()    { return moveTo(OrderStatus.PICKED); }
    public StatusChanged deliver()   { return moveTo(OrderStatus.DELIVERED); }
    public StatusChanged cancel()    { return moveTo(OrderStatus.CANCELLED); }

    private synchronized StatusChanged moveTo(OrderStatus to) {
        if (!status.canMoveTo(to)) throw new IllegalTransitionException(id, status, to);
        var event = new StatusChanged(id, status, to, Instant.now());
        status = to;
        version++;
        return event;
    }

    public synchronized OrderStatus status() { return status; }
}
```

The service is the orchestrator: load, transition, save, then publish. Listeners are injected, so analytics later is one new class plus one line of wiring.

```java
public final class OrderService {
    private final OrderRepository repo;
    private final List<OrderStatusListener> listeners;

    public OrderService(OrderRepository repo, List<OrderStatusListener> listeners) {
        this.repo = repo; this.listeners = List.copyOf(listeners);
    }

    public void cancel(String orderId) { transition(orderId, Order::cancel); }
    public void confirm(String orderId) { transition(orderId, Order::confirm); }
    // ... one per action

    private void transition(String orderId, Function<Order, StatusChanged> action) {
        Order o = repo.get(orderId);
        StatusChanged e = action.apply(o);          // throws on illegal transition, nothing published
        repo.saveIfVersionMatches(o);               // UPDATE ... WHERE id=? AND version=?; conflict -> retry/409
        publish(e);                                 // only after the change is durable
    }

    private void publish(StatusChanged e) {
        for (var l : listeners) {
            try { l.onStatusChanged(e); }
            catch (RuntimeException ex) { log.warn("listener {} failed for {}", l, e, ex); }
        }
    }
}

final class CustomerNotifier   implements OrderStatusListener { /* push/SMS to customer */ }
final class RestaurantNotifier implements OrderStatusListener { /* restaurant dashboard */ }
// later: final class AnalyticsRecorder implements OrderStatusListener { ... }
```

### Notes for the real system
- **Notifications must not block or fail the transition.** In-process listeners are fine to start; sending SMS/push should go through a job queue (or an outbox table written in the same transaction as the status update) so a slow SMS provider doesn't hold the request and a crash between "saved" and "notified" doesn't lose the notification. The listener interface stays the same; `CustomerNotifier` just enqueues.
- **Concurrency across instances:** `synchronized` protects one JVM. With several app servers, the `version` column (optimistic lock) makes the cancel/confirm race produce exactly one winner.
- Store transitions in an `order_status_history` table if support needs the timeline; it is a natural listener too.

## Tests (sample)
```java
@ParameterizedTest @EnumSource(value = OrderStatus.class, names = {"PLACED", "CONFIRMED", "COOKING"})
void cancellableStates(OrderStatus from) { assertTrue(from.canMoveTo(OrderStatus.CANCELLED)); }

@Test void cannotCancelAfterPickup() {
    Order o = orderIn(OrderStatus.PICKED);
    assertThrows(IllegalTransitionException.class, o::cancel);
    assertEquals(OrderStatus.PICKED, o.status());
}

@Test void terminalStatesHaveNoExits() {
    for (var to : OrderStatus.values()) {
        assertFalse(OrderStatus.DELIVERED.canMoveTo(to));
        assertFalse(OrderStatus.CANCELLED.canMoveTo(to));
    }
}

@Test void everyListenerNotifiedOnceEvenIfOneThrows() {
    var a = new RecordingListener(); var boom = (OrderStatusListener) e -> { throw new RuntimeException(); };
    var b = new RecordingListener();
    var svc = new OrderService(repoWith(new Order("o1")), List.of(a, boom, b));
    svc.confirm("o1");
    assertEquals(1, a.events.size()); assertEquals(1, b.events.size());
    assertEquals(OrderStatus.CONFIRMED, repo.get("o1").status());
}

@Test void illegalTransitionPublishesNothing() {
    var a = new RecordingListener();
    var svc = new OrderService(repoWith(orderIn(OrderStatus.DELIVERED)), List.of(a));
    assertThrows(IllegalTransitionException.class, () -> svc.cancel("o1"));
    assertTrue(a.events.isEmpty());
}

@RepeatedTest(500) void cancelAndConfirmRaceHasOneWinner() { /* two threads, latch start, exactly one succeeds */ }
```
