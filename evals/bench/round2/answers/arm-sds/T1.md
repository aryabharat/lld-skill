# T1 Parking lot: fee calculation and spot allocation

## Assumptions (stated, since nobody is around to confirm)
- One lot, a handful of floors, a few hundred to a few thousand spots, a handful of gates. Everything fits in one process's memory; the gates are threads (or requests) inside one service. If gates were separate services, the same allocation logic moves into a DB row update (noted at the end).
- Spot sizes: SMALL (bike), MEDIUM (car), LARGE (truck). A bike may use a larger spot if no small one is free; a truck only fits LARGE. Allocation prefers the smallest fitting size, lowest floor first.
- Fee is charged at exit on the duration parked. Money is held as `long` minor units (paise/cents), never `double`.
- "Weekday vs weekend" is decided by the entry time in the lot's time zone (a stay that crosses midnight Friday to Saturday is billed at the entry-day rate in v1; splitting per segment is listed as a later rule).
- Time comes from an injected `Clock` so tests are deterministic.

## Requirements for this slice
1. `enter(vehicle)` returns a ticket with an assigned spot, or a clear "lot full for this vehicle type" result.
2. No spot is ever assigned to two vehicles, even when gates call `enter` at the same instant.
3. `exit(ticket)` computes the fee and frees the spot exactly once.
4. Fee = base rate (vehicle type x weekday/weekend) x billable hours, then any further rules (night rate, member discount, event surcharge) applied without editing existing code.
5. The fee result says which rules applied (support desk and finance will ask "why did I pay this?").

Out of scope: payments, reservations, display boards.

## Entities
| Entity | State | Behaviour |
|---|---|---|
| `ParkingLot` (orchestrator / facade) | allocator, pricing, active tickets | `enter`, `exit` |
| `SpotAllocator` | free spots per size | `allocate(VehicleType)`, `release(Spot)` |
| `Spot` | id, floor, size | immutable value |
| `Ticket` | id, vehicle, spot, entry time, closed flag | `close()` once |
| `PricingPolicy` | ordered list of `PricingRule` | `quote(ParkingSession)` |
| `PricingRule` | rule-specific config | `apply(session, runningQuote)` |

One pattern earns its place here: a list of small pricing rules (Strategy-style, composed in order). Allocation needs no pattern, just the right concurrent data structure.

## Correctness tests, written before the code

### Pricing
- Given car, Tuesday 10:00-12:00, car weekday rate 40/h, when quoted, then 80 and applied rules = [BASE].
- Given car, Saturday 10:00-12:00, weekend rate 60/h, then 120.
- Given bike / truck, each uses its own rate (table-driven test over all 6 type x day cells).
- Edge: 0 minutes parked -> minimum charge of 1 hour (product rule; assert it explicitly). 61 minutes -> 2 hours (round up). Exactly 60 minutes -> 1 hour.
- Edge: entry Friday 23:30, exit Saturday 01:00 -> billed at weekday rate (v1 assumption is pinned by a test so a later change is deliberate).
- Edge: exit before entry (clock skew) -> `IllegalArgumentException`.
- Extensibility: given a new `MemberDiscountRule(10%)` added to the policy list, then the quote is 10% lower and `appliedRules` contains MEMBER_DISCOUNT, and no existing class changed.
- Ordering: surcharge then discount gives a defined result; test pins the order (discount applies to the surcharged amount).
- Invariant: total is never negative; a discount rule cannot drive it below 0.

### Allocation
- Given an empty lot with 1 MEDIUM spot, when a car enters, then it gets that spot; a second car gets `LotFull`.
- Given only LARGE free, a bike gets the LARGE spot; a car with only SMALL free gets `LotFull`; a truck never gets SMALL/MEDIUM.
- Prefers smallest fitting size and lowest floor.
- After `exit`, the spot is allocatable again.
- Error: `exit` on an already closed ticket -> `IllegalStateException`, and the spot is not released twice (free count unchanged).
- Concurrency invariant: N spots, M > N threads calling `enter` at the same moment behind a `CountDownLatch` start gate -> exactly N succeed, M - N get `LotFull`, and all N assigned spot ids are distinct. Run it 1000 times in a loop.
- Concurrency: concurrent enter/exit churn for a few seconds -> at the end, free + occupied == total, no spot both free and occupied.

## Trace
Lot: floor 0 has M1 (MEDIUM); floor 1 has L1 (LARGE). Gates A and B both call `enter(car)` at once.
1. Both call `allocator.allocate(CAR)`; the fitting sizes are [MEDIUM, LARGE].
2. Both `poll()` the MEDIUM queue. `ConcurrentLinkedQueue.poll` is atomic: A gets M1, B gets `null`.
3. B moves on to LARGE and gets L1. Both cars are parked, in different spots. A third car gets `LotFull`.
4. A exits Saturday after 2h10m: `PricingPolicy` -> BASE (weekday? no, weekend 60/h x 3h = 180) -> any further rules -> `Quote(180, [BASE])`. Ticket closes, M1 goes back on the MEDIUM queue.
This matches the allocation and pricing tests above.

## Code (critical path)

```java
public enum VehicleType { BIKE, CAR, TRUCK }
public enum SpotSize { SMALL, MEDIUM, LARGE }

public record Spot(String id, int floor, SpotSize size) {}
public record Vehicle(String plate, VehicleType type, boolean member) {}

// ---------- Allocation ----------
public final class SpotAllocator {
    private static final Map<VehicleType, List<SpotSize>> FITS = Map.of(
        VehicleType.BIKE,  List.of(SpotSize.SMALL, SpotSize.MEDIUM, SpotSize.LARGE),
        VehicleType.CAR,   List.of(SpotSize.MEDIUM, SpotSize.LARGE),
        VehicleType.TRUCK, List.of(SpotSize.LARGE));

    // One lock-free queue of free spots per size. poll() hands a spot to exactly one caller.
    private final Map<SpotSize, Queue<Spot>> free = new EnumMap<>(SpotSize.class);

    public SpotAllocator(Collection<Spot> spots) {
        for (SpotSize s : SpotSize.values()) free.put(s, new ConcurrentLinkedQueue<>());
        spots.stream()
             .sorted(Comparator.comparingInt(Spot::floor).thenComparing(Spot::id))
             .forEach(s -> free.get(s.size()).add(s));
    }

    public Optional<Spot> allocate(VehicleType type) {
        for (SpotSize size : FITS.get(type)) {
            Spot s = free.get(size).poll();        // atomic: no two gates get the same spot
            if (s != null) return Optional.of(s);
        }
        return Optional.empty();
    }

    void release(Spot spot) { free.get(spot.size()).add(spot); }

    int freeCount(SpotSize size) { return free.get(size).size(); } // for tests/metrics only
}
```

Why a queue per size and not `synchronized`: there is no check-then-act; `poll()` is the check and the claim in one atomic step, so gates never block each other. A single `synchronized allocate()` would also be correct and is a fine choice if strict "lowest floor first" ordering under release matters more (a released spot goes to the queue tail). I'd start with the queue; switch to a `PriorityBlockingQueue` per size if strict floor ordering becomes a requirement.

```java
// ---------- Tickets and the facade ----------
public final class Ticket {
    private final String id; private final Vehicle vehicle; private final Spot spot; private final Instant entry;
    private final AtomicBoolean closed = new AtomicBoolean(false);
    Ticket(String id, Vehicle v, Spot s, Instant entry) { this.id = id; this.vehicle = v; this.spot = s; this.entry = entry; }
    boolean close() { return closed.compareAndSet(false, true); } // true only for the first caller
    // getters omitted
}

public sealed interface EntryResult {
    record Parked(Ticket ticket) implements EntryResult {}
    record LotFull(VehicleType type) implements EntryResult {}
}

public final class ParkingLot {
    private final SpotAllocator allocator;
    private final PricingPolicy pricing;
    private final Clock clock;

    public ParkingLot(SpotAllocator a, PricingPolicy p, Clock c) { allocator = a; pricing = p; clock = c; }

    public EntryResult enter(Vehicle v) {
        return allocator.allocate(v.type())
            .<EntryResult>map(spot -> new EntryResult.Parked(
                new Ticket(UUID.randomUUID().toString(), v, spot, clock.instant())))
            .orElseGet(() -> new EntryResult.LotFull(v.type()));
    }

    public Quote exit(Ticket t) {
        if (!t.close()) throw new IllegalStateException("ticket already closed: " + t.id());
        Quote q = pricing.quote(new ParkingSession(t.vehicle(), t.entry(), clock.instant()));
        allocator.release(t.spot());               // released exactly once, guarded by close()
        return q;
    }
}
```

```java
// ---------- Pricing ----------
public record ParkingSession(Vehicle vehicle, Instant entry, Instant exit) {
    public ParkingSession {
        if (exit.isBefore(entry)) throw new IllegalArgumentException("exit before entry");
    }
    public long billableHours() {
        long minutes = Duration.between(entry, exit).toMinutes();
        return Math.max(1, (minutes + 59) / 60);   // round up, minimum one hour
    }
}

public record Quote(long amountMinor, List<String> appliedRules) {
    Quote plus(long delta, String rule) {
        var rules = new ArrayList<>(appliedRules); rules.add(rule);
        return new Quote(Math.max(0, amountMinor + delta), List.copyOf(rules));
    }
}

/** One pricing rule. Returns the quote unchanged if it does not apply. */
public interface PricingRule {
    Quote apply(ParkingSession s, Quote current);
}

public final class PricingPolicy {
    private final List<PricingRule> rules;          // order matters and is explicit
    public PricingPolicy(List<PricingRule> rules) { this.rules = List.copyOf(rules); }
    public Quote quote(ParkingSession s) {
        Quote q = new Quote(0, List.of());
        for (PricingRule r : rules) q = r.apply(s, q);
        return q;
    }
}

/** Today's rule: hourly rate by vehicle type and weekday/weekend. A table, not a class per cell. */
public final class BaseRateRule implements PricingRule {
    private final Map<VehicleType, Long> weekdayPerHour, weekendPerHour;
    private final ZoneId zone;
    public BaseRateRule(Map<VehicleType, Long> wd, Map<VehicleType, Long> we, ZoneId zone) {
        weekdayPerHour = Map.copyOf(wd); weekendPerHour = Map.copyOf(we); this.zone = zone;
    }
    public Quote apply(ParkingSession s, Quote q) {
        DayOfWeek d = s.entry().atZone(zone).getDayOfWeek();
        boolean weekend = d == DayOfWeek.SATURDAY || d == DayOfWeek.SUNDAY;
        long rate = (weekend ? weekendPerHour : weekdayPerHour).get(s.vehicle().type());
        return q.plus(rate * s.billableHours(), "BASE");
    }
}

// Coming rules are new classes added to the list; nothing above changes.
public final class MemberDiscountRule implements PricingRule {
    private final int percent;
    public MemberDiscountRule(int percent) { this.percent = percent; }
    public Quote apply(ParkingSession s, Quote q) {
        if (!s.vehicle().member()) return q;
        return q.plus(-q.amountMinor() * percent / 100, "MEMBER_DISCOUNT");
    }
}
// EventSurchargeRule(eventCalendar, flatAmount), NightRateRule(window, rate) follow the same shape.
```

class SpotAllocatorTest {
    @Test void bikeFallsBackToLargerSpotTruckDoesNot() { /* ... */ }

    @RepeatedTest(1000)
    void concurrentGatesNeverShareASpot() throws Exception {
        int spots = 50, cars = 200;
        var allocator = new SpotAllocator(mediumSpots(spots));
        var start = new CountDownLatch(1);
        var pool = Executors.newFixedThreadPool(16);
        List<Future<Optional<Spot>>> results = new ArrayList<>();
        for (int i = 0; i < cars; i++)
            results.add(pool.submit(() -> { start.await(); return allocator.allocate(CAR); }));
        start.countDown();
        List<Spot> got = new ArrayList<>();
        for (var f : results) f.get().ifPresent(got::add);
        pool.shutdown();
        assertEquals(spots, got.size());                        // exactly N winners
        assertEquals(spots, new HashSet<>(got).size());         // all distinct
        assertEquals(0, allocator.freeCount(SpotSize.MEDIUM));
    }
}

## Deliberately not done
- No Factory for vehicles or spots (the caller knows the type), no Singleton lot (inject it), no class per vehicle type (a rate table covers it).
- No distributed lock. If gates become separate processes, the allocator becomes one SQL statement: `UPDATE spots SET occupied_by = ? WHERE id = (SELECT id FROM spots WHERE size = ANY(?) AND occupied_by IS NULL ORDER BY size, floor LIMIT 1 FOR UPDATE SKIP LOCKED) RETURNING id;` and the same concurrency test runs against a real Postgres.
- Later list: per-segment billing across midnight/night windows (would make `NightRateRule` split the session), rule config from a DB table, spot reservations.
